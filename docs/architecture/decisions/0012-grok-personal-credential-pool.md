# ADR 0012: File-backed credential management and ordered pools

## Status

Accepted. Configuring a pool does not authorize live credential operations, migration or inference.

## Decision

- The [manager](../../../src/credential/manager.rs) owns provisioned API keys and profile-bound OAuth grants with separate lifecycles. Registered [drivers](../../../src/credential/driver.rs) own authority/client wire, verified identity, grant inheritance and revocation; manager/store do not branch on inference Provider identity. API keys do not fabricate an OAuth principal. [ID-token validation](../../../src/credential/jwt.rs) delegates JOSE/JWK and signature mechanics to jsonwebtoken; fixed algorithms, unique trusted key selection, OIDC identity/nonce and profile time policy remain explicit. Header key URLs never select authority.
- The [store](../../../src/credential/store.rs) merges independently owned API-key, OAuth and pool records into bounded Provider-namespace JSON documents. OAuth profiles remain distinct from inference Providers; a pool may reference a profile-bound account without copying its grant. Revisions, material generations, login tickets and replay epochs have separate meanings. Duplicate/unknown fields, inconsistent identity and obsolete layouts fail closed; no implicit migration or auth-cache import exists.
- [Filesystem safety](../../../src/credential/storage_fs.rs) uses fs-mistrust with environment bypass disabled, atomicwrites for replacement/durability, and standard-library file locks. [Windows ACL validation](../../../src/credential/storage_windows.rs) supplements fs-mistrust's documented permission-check gap. Platform limitations must fail closed rather than silently downgrade privacy or publication guarantees. Library availability is not native-platform or filesystem acceptance evidence.
- Stable operation and transaction locks are separate from replaced documents. Short transactions reread the latest document and merge only the selected record. No document transaction spans authority I/O or human interaction; conflicting operations return busy. OAuth publication revalidates ticket/client/principal and uniqueness; a failed login preserves the existing session.
- Refresh durably removes reusable secrets and supersedes pending login tickets before transmission. Cancellation, rejection or uncertain consumption requires reauthorization. SIWC replacements are published to a non-borrowable pending-verification state before JWKS verification; an explicit refresh can finish verification without consuming the old refresh token again. Per-record recovery markers are durably armed before replacement and cleared only after confirmed publication; a retained marker never restores old material. API-key replacement/removal or OAuth login/logout are explicit recovery operations.
- Dynamic registration retains an issued client before code exchange, separately from verified principal and active grant. The selected store owns a stable host identifier; returning login reuses that registration and validates the original principal. Identity-only grants do not authorize plan usage. SIWC access is single-registration, single-attempt and non-fallback; multiple saved registrations are not a rotation pool.
- API-key add, revision-checked replace, enable/disable, local removal and redacted status share storage safety, not OAuth state. Key bindings pin private identity, material generation, replay epoch and an internal material digest; replacement or state changes invalidate old bindings, including after re-enable. Removal retains a secret-free tombstone and does not claim upstream revocation or secure erasure.
- [OAuth access bindings](../../../src/credential/access.rs) pin profile/client/verified principal, including workspace. Access rotation preserves that identity; expiry, logout, quarantine or identity change rejects later borrows. Unknown expiry stays unknown. Already-borrowed attempt snapshots may finish without filesystem locks; ordinary requests never log in or refresh.
- [Pools](../../../src/credential/pool.rs) declare ordered credential references and bounded, opt-in fallback. They provide compatible bindings, not HTTP retry loops, load balancing or account discovery. [Gateway activation](../../../src/gateway/bootstrap.rs) reads explicit private configuration and pool files only, with no environment secret/alias fallback. Endpoint auth contracts validate every member; equal Provider names or Bearer syntax do not make grants interchangeable.
- [Execution](../../../src/gateway/exchange.rs) advances fixed `(endpoint, credential)` candidates under one Route budget and absolute deadline. Local unavailability and permitted transient failures may advance only before downstream publication. Storage/security failures, identity changes, upstream auth/permission errors and unknown-scope 429s do not authorize same-Provider credential switching. Pool and configuration limits only narrow the chain. Detailed publication policy is owned by [ADR 0010](0010-canonical-model-fixed-fallback.md).
- Multiple credentials do not share an issuer scope. Until an explicit client-carried affinity contract exists, multi-member ingress rejects source-bound opaque continuation/encrypted-output requests. Business data never selects credentials, auth headers, origins or scripts. Credential locators and secrets stay outside task IR and downstream diagnostics.

## Rationale and consequences

Mature libraries own generic CLI, filesystem and serialization mechanics; MorphieCore retains identity, refresh-consumption, replay and fallback policy. File-only activation removes competing environment/file selection paths. Concurrent CLI management does not require a new daemon or stopping the Gateway, but it still requires cooperating writers and a local filesystem supporting the selected guarantees.

This is not distributed coordination, remote key provisioning, automatic refresh, quota recovery or session affinity. Fallback can duplicate upstream work and billing; local cancellation/removal cannot prove upstream termination. A malicious same-user process or trusted administrator is outside filesystem privacy isolation.

Operations and recovery: [credential guide](../../credentials.md). Authorization provenance: [Grok](../../references/grok-login.md), [SIWC](../../references/siwc-login.md). Format, bounds and independent regressions belong to the owning code and tests, not inventories or execution diaries.
