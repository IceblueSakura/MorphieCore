# Native static image targets — 2026-11-23

These source observations inform the [accepted Qwen profile](../architecture/adaptation-and-dialects.md#native-static-images) and do not select Google or Grok activation.

| Target | Official contract and observed boundary |
|---|---|
| `qwen-image-3.0-pro` | The [Aliyun native API](https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference) supports synchronous `parameters.response_format=b64_json`. The [Token Plan example](https://help.aliyun.com/zh/model-studio/token-plan-image-generation) uses a URL, but the same inline option works on both configured origins. Native results carry PNG data URLs, a `stop` terminal and image-count/dimension metering, but no `created`. Aliyun documents a workspace-scoped OpenAI-compatible endpoint; the configured legacy DashScope origin does not serve that image path. Do not infer OpenAI compatibility from model availability or reuse a response-head date as a creation timestamp. |
| `gemini-nano-banana-2.1` | [Gemini image generation](https://ai.google.dev/gemini-api/docs/image-generation) selects this stable successor to the deprecated `gemini-3.1-flash-image`. A `generateContent` request with text/image response modalities completed with inline JPEG, `STOP` and no creation report. Image output is a separate capability from image input to Generation Text. `gemini-3-pro-image` and `gemini-3.1-flash-lite-image` are distinct Pro and Lite variants. The [migration table](https://ai.google.dev/gemini-api/docs/deprecations) directs Imagen 4 users to Nano Banana 2.1. |
| `grok-imagine-image-2.0` | [xAI's standalone endpoint](https://docs.x.ai/developers/rest-api-reference/inference/images) supports `b64_json` and reports artifact MIME and native accounting. A request through the configured OAuth binding returned an inline JPEG with MIME and cost reports but no `created`. These results do not meet the strict GPT Image contract; choose native encoding and accounting dispositions before activation. |
